## BLOQUANT

### B1 — 125 offres Estée Lauder envoient le candidat sur UNE AUTRE offre
- **Fait** : `elc_url_mismatch` = **125** offres actives de `estee-lauder-companies` dont `Job.url` ne se termine pas par leur `externalId`. Exemple `cmtnhcub523q6qq4zqpk2pzhu` « Beauty Advisor MAC Truworths Gateway FFT 173.36hr » (Durban), externalId `1168273610474`, url `…/careers/job/1168274067860`. Vérifié à la source : `GET elcompanies.eightfold.ai/api/pcsx/position_details?position_id=1168273610474` → http 200, `name` identique, `positionUrl: "/careers/job/1168273610474"`. Le lien stocké pointe donc sur une autre position. Même mécanisme derrière `doublons_meme_url` : 4 offres distinctes de Manchester (4 externalId) partagent l'URL `…/1168275251425`.
- **Impact** : « Postuler chez Estée Lauder » ouvre une offre qui n'est pas celle lue (autre ville, autre contrat). C'est la promesse D18 rompue.
- **Cause** : `src/ats/adapters/eightfold.ts:105-113` — `positionUrl` est pris tel quel depuis la liste `positions`, où Eightfold renvoie l'URL **canonique du groupe** de positions similaires, pas celle de la position.
- **Correction** : `url: position.id ? \`${origin}/careers/job/${position.id}\` : positionUrl` (1 ligne) + test `url.endsWith(externalId)` sur le fixture. Vérification : `elc_url_mismatch` = 0 après le run suivant.

### B2 — L'Oréal (Avature) : du JavaScript affiché comme description, « /a> » comme lieu
- **Fait** : `location_a_tag` = **71** offres actives `l-oreal-professionnel` avec `location = "/a>"` (ville NULL). **3** offres ont pour description 451 caractères de script : `"/a> var socialShareButtons = tpt.selectAll(\"div.article__header__actions#jobId254985 …"`. Vérifié sur le site : `https://modecareers.com/offre/tempo-kiehl-s-eaton-cmtoom9gb28mnqq4zbm50cuo5` → http 200, ce texte est dans la meta `description` et dans le JSON-LD `JobPosting.description`.
- **Impact** : le candidat (et Google) lisent du code à la place de l'offre.
- **Cause** : `src/ats/adapters/avature.ts:60-66` — le lieu est capturé par `/<meta name="description" content="[^"|]*\|\s*([^"|]{2,60})\s*\|/` sur une meta que la page L'Oréal remplit parfois avec un fragment HTML ; `:72-75` — la description vient de `og:description` / `meta description` (texte aplati, d'où aussi 1 382 « pavés » sans saut de ligne, cf. I8). `be1bbf4` fait passer la description complète par `parseMicrodataDescription` (`:446`) mais garde la meta en repli et ne touche pas au lieu.
- **Correction** : rejeter toute capture contenant `<`, `>`, `var ` ou `function(` ; ne jamais prendre le lieu dans la meta (le listing `parseAvatureListing` le porte) ; ne jamais retomber sur `og:description` si la microdata est vide (mieux vaut NULL, D1). ~4 lignes.
